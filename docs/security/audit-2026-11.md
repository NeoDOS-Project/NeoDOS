# Full security audit — November 2026

> **Issue:** #112 (`SEC-AUDIT-FULL`)
> **Scope:** syscall boundary, Object Manager, VFS, Registry, user copies,
> integer arithmetic, TOCTOU and handle-table lifecycle.
> **Method:** source review against `develop`, invariant checks (`cargo build`,
> kernel test suite) and new regression tests. This is a code audit, not a
> fuzzing campaign; fuzzing remains tracked by #113/#114.

## Findings

| ID | Severity | Subsystem | Finding | Status |
| ---- | -------- | --------- | ------- | ------ |
| SEC-112-01 | Low | User copies | `copy_from_user` / `copy_to_user` / `copy_user_string` computed `base + offset` without overflow checks; a wrapped address could pass validation as a different user page. | **Fixed**: checked `user_addr()` in `syscall/util.rs`. |
| SEC-112-02 | Low | User strings | `copy_user_string` silently truncated a 255-byte string without NUL, so callers could act on a prefix. | **Fixed**: unterminated strings now return `EFAULT`. |
| SEC-112-03 | Medium | Syscall allocations | Handlers sized kernel allocations directly from user `buf_size`/`data_len`; a Ring-3 caller could exhaust the 16 MB heap (#764). | **Mitigated**: central `MAX_OB_IO_BUF` (64 KiB) for `ob_query_info`/`ob_set_info` and `MAX_VALUE_DATA` (64 KiB) for Registry writes. Per-class review remains in #764. |
| SEC-112-04 | Low | VFS | `Vfs::read/write/stat/readdir` indexed `drives[drive_idx]` without a bounds check, turning an invalid index into a kernel panic. | **Fixed**: all four use `get_mut(...).ok_or(NotFound)`. |
| SEC-112-05 | Medium | Registry | `Hive::alloc_cell` grew the cell vector beyond `MAX_CELLS` while `deserialize` rejects indexes `>= MAX_CELLS`: a large hive consumed unbounded memory and could not be reloaded. | **Fixed**: the hive is fixed-capacity again and returns `None` when full. |
| SEC-112-06 | Low | Registry | No upper bound on a single Registry value payload. | **Fixed**: `MAX_VALUE_DATA` (64 KiB) enforced in the syscall and `Hive::set_value`. |
| SEC-112-07 | Info | Handle table | Handles have no generation counter: after `close`, a reused fd can reference a different object (classic fd-reuse aliasing). | **By design** (u8 fd ABI, POSIX-like reuse). Documented; adding generations would be an ABI change. |
| SEC-112-08 | Info | Syscall boundary | `copy_user_string` caps names at 254 characters and now fails closed on unterminated input. | **Documented**; callers receive `EFAULT`. |

## Positive controls confirmed

- **Dispatch:** `syscall_dispatch` rejects `RAX >= 256`, unassigned SSDT slots and
  non-admin callers of `ADMIN-ONLY` entries (`check_syscall_permission`); boot
  `validate_abi()` asserts every assigned slot is present.
- **Object Manager:** `IdIndex` makes `ObId` lookup O(1); refcount saturation is
  counted (`OB_REF_OVERFLOW`); close/finalize ordering was hardened in #661.
- **VFS:** `..` cannot climb above the root, paths are capped at 32 components,
  drive letters are validated, and namespace symlinks cap resolution at 10 hops.
- **Registry:** cell access goes through bounds-checked `slot`/`slot_mut`;
  deserialization validates every length before slicing and rejects cell indexes
  outside the fixed table.
- **User copies:** validation and access happen under
  `SCHEDULER -> USER_MEMORY_LOCK`, preventing validate-then-unmap TOCTOU
  (NEODOS-04 / #634); heap/mmap bytes require a PRESENT PTE.
- **Handle table:** fds 0–2 are reserved, the table is capped at 256 entries, and
  `alloc_two_handles` no longer truncates at the cap (#668).

## Regression tests added

| Test | Covers |
| ---- | ------ |
| `syscall_user_addr_checked` | Checked user-address arithmetic at `u64::MAX`. |
| `syscall_copy_from_user_rejects_wrapped_range` | Wrapped ranges fail with `EFAULT` in both copy directions. |
| `vfs_invalid_drive_index_rejected` | Invalid drive indexes return `NotFound`, never panic. |
| `cm_value_size_limit` | Registry accepts exactly `MAX_VALUE_DATA` and rejects one byte more. |
| `cm_hive_capacity_is_fixed` | A full hive cannot grow past its fixed cell table. |

## Fix list and follow-ups

1. **Done in this audit:** SEC-112-01, -02, -04, -05, -06; mitigation for -03.
2. **Open, tracked:** #764 (all remaining user-sized kernel allocations), #774
   (`sys_read`/`sys_write` >4 KiB), #763 (`sys_mmap` base), #761 (user window not
   reserved), #745 (heap range checks), #666 (buddy double-free detection).
3. **Design notes:** SEC-112-07 (handle generations) and SEC-112-08 (string cap)
   require an ABI decision, not a silent fix.
4. **Coverage:** syscall fuzzing (#113) and driver HST fuzzing (#114) are still the
   right next step for boundary discovery.

## Limitations

The audit reviewed the paths above by hand and exercised them with kernel tests.
It does not replace dynamic fuzzing, hardware-specific driver review, or a formal
threat model; those remain separate work items.
